# RF 的体积：要剪枝，基本不用量化

## 一个节点多少字节

从真实链出来的镜像反推（20 棵树 × 深 6 的森林，11,604 B，实测对得上）：

```
每个节点     14 B   feature uint16(2) + threshold f32(4) + left i32(4) + right i32(4)
每个叶子额外 12 B   n_classes × f32（3 分类）
```

满二叉树里叶子约占一半，所以：

> **约 20 B/节点**（3 分类）。这个数写成了测试（`test_体积公式_每节点约_20_字节`），
> 改了节点编码它会红——免得有人拿着过期的数去做预算。

## 预算反推

| flash 预算 | 能放多少节点 | 摊到 200 棵树 | 约等于深度 |
|---|---|---|---|
| 64 KB | 3,276 | 16 /棵 | 4 |
| 128 KB | 6,553 | 32 /棵 | 5 |
| 256 KB | 13,107 | 65 /棵 | 6 |

GR5513 一共 512KB flash，BLE 协议栈 + 应用实测占 104KB，所以给模型留 128KB
是个现实的上限（还要留 OTA 的余量）。

**每加一层深度，节点数翻倍**——这条也写成了测试。`n_estimators=200, max_depth=null`
在几万条窗口上训出来的森林，每棵几千到上万个节点很正常，那就是 **几十 MB 量级**，
比预算大两三个数量级。

所以：**RF 上端侧，剪枝不是优化，是前提。**

## 要不要像 NN 那样量化

**基本不用，先别做。** 两者的瓶颈不在一个地方：

| | NN | RF |
|---|---|---|
| 参数量 | 结构定了就固定 | **由数据决定**，可以差两三个数量级 |
| 主要杠杆 | 量化（f32→int8，4×） | **减节点数**（可以 100×） |
| 量化能拿到多少 | 4 倍 | 阈值 f32→int16 约省 20% |

超了 100 倍的时候，省 20% 没有意义。**先把节点数降下来，降完再看要不要抠那 20%。**

而且 RF 的量化**会改判决**：阈值量化到 int16 之后，特征值正好落在原阈值和新阈值
之间的样本会走反。这不是"精度损失"这种可以用一个数字概括的东西，得重新跑一遍
golden vector 和判别一致率。收益 20%、代价是一整轮验证，顺序上明显该排在后面。

真要抠体积，**优先级高于量化阈值**的是这两个：

1. **孩子下标 int32 → int16**：省 4 B/节点（20%），前提是整片森林节点数 < 65536。
   它**不改任何判决**，纯粹是存储。比量化阈值划算得多。
2. **叶子概率 f32 → uint8**（0-255 定点）：3 分类省 9 B/叶子。会改判决，但改的方式
   比量化阈值温和——概率只在最后相加，不参与路径选择。

## 限深就能塞下吗：能，但那时候 RF 已经不是 RF 了

**体积上能。** 满树上界 `棵数 × (2^(深度+1)-1) × 20 B`：

|  | d=3 | d=4 | d=5 | d=6 | d=7 |
|---|---|---|---|---|---|
| 50 棵 | 15KB ✓ | 30KB ✓ | 62KB ✓ | 124KB ✓ | 249KB ✗ |
| 100 棵 | 29KB ✓ | 61KB ✓ | 123KB ✓ | 248KB ✗ | 498KB ✗ |
| 200 棵 | 59KB ✓ | **121KB ✓** | 246KB ✗ | 496KB ✗ | 996KB ✗ |
| 300 棵 | 88KB ✓ | 182KB ~ | 369KB ✗ | 744KB ✗ | 1494KB ✗ |

（128KB 预算。真实的树不满，通常是上界的 40~70%，所以边界上的组合要实测。）

注意这几个 ✓ 的组合**节点总数其实差不多**——`棵数 × 2^深度` 是同一个预算，
多几棵和深一层是在换。

**但体积塞得下不等于该这么做。** RF 的准来自两件事：**深树给低偏差** +
**bagging 降方差**。限深把低偏差那一半直接拿掉了，而 bagging 只降方差、不降偏差——
一堆欠拟合的浅树平均起来，还是欠拟合。

而 GBDT 本来就是**为浅树设计的**：boosting 是一轮一轮拟合残差，偏差靠轮数补，
所以 `max_depth=6` 是它的常规配置不是妥协。

**所以「限深的 RF」约等于「一个更差的 GBDT」。** 要限深，不如直接换 GBDT。

这是统计上的一般规律，不是你这份数据的结论——**所以还是要测**。好在不用重训：

## 怎么剪：不用重训就能拿到曲线

```bash
python python/prune_rf.py --model xxx.pkl \
    --features holdout_feats.npy --labels holdout_y.npy \
    --min-samples-leaf 1,5,10,20
```

它把已经训好的树**就地截断**（在深度 d 处把节点直接当叶子用，类别分布取 sklearn
在那个节点上已经存好的 `value`），给出「深度 → 节点数 → flash → macro-F1」一整张表。

**为什么能不重训**：sklearn 在每个节点上都存了该节点的类别分布，所以截断是精确操作。

**它跟"训练时设 max_depth=d"不等价**——训练时限深，分裂点的选择会不同。
而且**方向是确定的：截断出来的结果 ≤ 重训的结果**。因为原来那些分裂是冲着
"后面还要再分好几层"去选的，半路砍掉等于用了一批并非为浅树优化的分裂点。

这个不等式很有用：**这张表是悲观的下界**。截断到 depth 4 如果已经能看，
那么按 `max_depth=4` 重训只会更好。反过来不成立——表上掉得厉害的，
重训**可能**救回来一些，值得再试一次再放弃。

读表的要点：

- 找**掉点最少且塞得下**的那一行，不是最小的那一行。
- 曲线通常有拐点：拐点前掉点很少（剪掉的是过拟合分支），之后陡降（开始剪到真信息）。
  停在拐点前一两档。
- 留出集别用训练集。训练集上剪枝永远显得掉点很多——被剪掉的正是那些把训练样本
  背下来的分支。
- 看 **macro-F1 不看准确率**：睡觉占绝大多数，一个"永远猜睡觉"的模型准确率很好看，
  而它在唯一有用的那一类上全错。

## 两个杠杆哪个先试

**先试 `min_samples_leaf`。** sklearn 默认是 1，意味着树会一直分到每个叶子只剩
一个样本——尾部那些分支覆盖一两个样本，是噪声不是信息。把它设成 5~20 通常能砍掉
大半节点而几乎不掉点。

限深（`max_depth`）更粗暴：它对所有分支一刀切，包括那些确实还有信息的深分支。
两个一起用效果最好，但先单独看一遍各自的曲线，才知道是谁在起作用。
